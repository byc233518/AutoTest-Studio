# JMOM 测试平台用户体验与运营能力完善设计

> 日期：2026-07-11
> 状态：自动批准执行

## 目标
把现有“场景 + 数据 + 执行 + 报告”工具升级为测试人员可自助使用的日常工作台，覆盖执行前、执行中、执行后以及平台运营维护闭环。

## 核心设计

### 1. 场景就绪度与执行预检
- 为每个场景计算脚本、数据集、环境、依赖四类就绪状态。
- 场景列表展示可执行、需准备、不可执行和草稿状态。
- 执行前弹窗展示逐项检查、修复入口和依赖链执行选项。

### 2. 业务化报告与失败恢复
- 运行记录保存总行数、成功行、失败行和结构化错误明细。
- 报告详情提供业务摘要、失败行下载、复制错误和仅重跑失败行。
- 技术日志、截图和录像保留为二级排障信息。

### 3. 工作台与信息治理
- 首页改为今日执行、成功率、待处理失败、可执行场景等行动指标。
- 增加最近失败、推荐任务、稳定性和场景负责人信息。
- 草稿场景独立过滤，数据集支持用途、环境和标签。

### 4. 测试套件与依赖链
- 支持创建测试套件并顺序执行场景。
- 执行场景时可自动补跑未满足依赖。
- 内置 WMS 主数据、MES 生产链、核心冒烟套件。

### 5. 数据生命周期
- 数据集支持唯一后缀、失败保留、执行后清理策略。
- 执行结果标记自动化数据批次，便于追踪和清理。

### 6. 调度、通知与质量指标
- 支持定时计划、启停和手动触发。
- 提供站内通知与 webhook 配置。
- 统计最近十次成功率、平均耗时、不稳定失败和自愈次数。

### 7. 安全与运维
- 首次登录强制修改默认密码，密码使用 scrypt 哈希。
- 增加审计日志、会话有效期和敏感配置脱敏。
- 保留 SQLite 本地模式，同时支持通过环境变量切换外部数据库的迁移说明。

### 8. 文档与引导
- 修正 Oracle 端口为 1521。
- 增加测试人员三步使用手册、场景成熟度定义和常见失败处理。
