# AutoTest Studio录制、编辑与本地执行体验设计

> 日期：2026-07-18  
> 状态：已确认  
> 范围：快速录制、脚本与测试数据在线编辑、字段双向同步、发布版本、本地执行

## 1. 目标

在保留现有 Vue 3、Express、SQLite、Playwright 和免安装录制器架构的前提下，把场景维护收敛为一条短流程：

```text
录制 -> 识别字段与成功条件 -> 在线编辑 -> 本地或服务器验证 -> 发布
```

目标如下：

1. 用户无需手工执行命令即可发起录制。
2. 录制脚本能够快速转换为数据驱动脚本，而不是只保存原始 Codegen 代码。
3. 脚本、测试数据和字段定义均可在平台在线维护。
4. 平台字段和脚本 `testDataSchema` 都可以作为修改入口，并提供明确的冲突解决流程。
5. 用户可以从场景直接选择本地执行，桌面客户端优先一键唤起，绿色工具作为回退。
6. 场景只保留“草稿”和“已发布”两个状态，每次发布保存一个只读版本。

## 2. 设计原则

- 所有登录用户能力一致，不引入审核角色或额外权限流。
- 草稿允许执行，发布不是执行前置条件。
- 发布版本是不可变快照；日常保存仍写入当前工作副本。
- 使用结构化 JavaScript 解析器处理脚本，不用正则替换代码。
- 已有录制码、本地执行码、Runner、报告上传和脚本版本能力继续复用。
- 不建设完整低代码测试引擎，不把 Playwright 脚本拆成平台自有步骤 DSL。

## 3. 场景状态与发布版本

场景只包含两种状态：

- `draft`：当前工作副本存在未发布修改，可执行。
- `published`：当前工作副本与最近一次发布快照一致。

以下操作会把已发布场景自动改为草稿：

- 修改基本信息或字段定义。
- 保存、上传或重新录制脚本。
- 完成字段同步或测试数据字段迁移。
- 恢复历史发布版本后继续修改。

点击“发布”时执行以下动作：

1. 校验脚本语法、字段冲突和脚本入口。
2. 对没有成功条件的场景给出警告，允许用户明确确认后继续。
3. 保存场景配置、脚本内容、字段定义和字段同步关系的只读快照。
4. 生成递增版本号，例如 `v1`、`v2`。
5. 将当前场景状态改为 `published`。

历史发布版本支持查看、脚本和字段差异比较、恢复为当前草稿。测试数据集独立管理，不在每次发布时重复复制。

## 4. 场景工作区

场景详情采用统一工作区，保留五个页签：

1. **基本信息**：名称、应用、模块、优先级和说明。
2. **测试数据**：字段定义、在线表格、数据集、Excel 导入导出和数据迁移。
3. **脚本与录制**：录制入口、脚本分析结果、代码编辑器和字段同步。
4. **发布版本**：发布、版本列表、差异比较和恢复。
5. **执行记录**：本场景的服务器与本地执行历史、报告和过程证据。

页面头部固定展示场景状态、当前脚本、字段数量、最近执行结果，以及“执行”和“发布”两个主要操作。

## 5. 快速录制

### 5.1 启动方式

用户选择环境并点击“开始录制”后，平台创建 30 分钟有效的一次性录制任务，并生成：

- 自定义协议地址：`autotest-recorder://record?...`
- 兼容现有绿色工具的八位录制码。

平台先尝试打开自定义协议，同时显示回退区域：

- 复制录制码。
- 下载绿色免安装工具。
- 手工打开工具后的操作提示。

桌面程序提供“启用平台一键启动”功能，通过当前用户注册表注册 `autotest-recorder` 协议，不要求管理员权限。未注册协议时，绿色免安装流程仍然完整可用。

### 5.2 录制完成

录制器继续使用 Playwright Codegen。关闭 Inspector 后：

1. 录制器上传原始脚本。
2. 服务端解析脚本并生成分析结果。
3. 场景状态改为草稿。
4. 平台自动打开录制后处理向导。

上传失败时保留现有重试能力；重复提交通过录制任务 ID 和内容哈希保持幂等。

## 6. 录制后处理向导

向导包含三步。

### 6.1 字段识别

从 `fill`、`type`、`selectOption`、`check`、`setInputFiles` 等操作提取固定值，生成候选字段。每个字段可维护：

- 字段 key。
- 显示名称。
- 类型：文本、数字、日期、布尔、选项、文件。
- 是否必填。
- 示例值。

用户可以合并候选字段、忽略固定值或改名。确认后，平台生成参数化脚本和示例数据行。

### 6.2 成功条件

平台提取现有 `expect` 断言。没有断言时，用户可以增加常用成功条件：

- 文本可见。
- 元素可见。
- URL 包含指定内容。
- 输入值等于指定内容。

成功条件被转换为标准 Playwright `expect` 代码。平台不自动猜测复杂业务正确性。

### 6.3 生成预览

最终一步并排展示：

- 参数化后的 Playwright 脚本。
- 字段定义。
- 示例测试数据。
- 发现但未处理的警告。

确认后覆盖当前草稿；取消则保留原始录制文件，不改动当前脚本。

## 7. 脚本在线编辑

现有普通文本框替换为代码编辑器，至少支持：

- JavaScript 语法高亮和括号匹配。
- 搜索、替换和行号。
- 格式化。
- 基础语法错误提示。
- 未保存修改提醒。
- 当前草稿与发布版本对比。

保存脚本时，服务端执行语法解析和字段提取。解析失败不覆盖当前有效脚本，并返回精确的行列位置。

## 8. 字段双向同步

平台字段定义和脚本 `testDataSchema` 都允许修改。每次保存任一侧时计算结构化差异：

- 新增字段。
- 删除字段。
- 重命名字段。
- 必填状态变化。
- 类型或示例值变化。

存在差异时，用户可以选择：

1. 使用平台字段更新脚本。
2. 使用脚本字段更新平台。
3. 手工映射后合并。

脚本侧更新使用 AST 和受控的 schema 代码块。字段重命名会同步修改可静态识别的 `data.field` 和 `data['field']` 引用。动态属性访问无法安全更新时，阻止覆盖并列出位置。

## 9. 测试数据与字段迁移

字段删除、重命名或新增必填字段影响已有数据集时，进入迁移向导：

1. 展示受影响的数据集和行数。
2. 将旧字段映射到新字段。
3. 为新增字段填写默认值，或逐行补充。
4. 预览迁移后的前若干行及校验错误。
5. 确认后创建迁移后的新数据集版本。

原数据文件和行数据保持不变。迁移失败不产生半成品数据集；迁移结果记录来源数据集和字段映射，支持追溯。

在线数据表格继续支持新增、删除、复制行、批量粘贴、CSV/Excel 导入、模板下载和规则/AI 生成。执行时始终绑定明确的数据集 ID。

## 10. 本地执行

场景列表和场景工作区均提供“执行”按钮。执行弹窗保留：

- 执行环境。
- 执行位置：服务器、本地。
- 浏览器模式。
- 测试数据集。

选择本地执行后：

1. 平台创建排队中的运行任务和一次性执行凭证。
2. 优先打开 `autotest-recorder://execute?...`。
3. 同时提供执行码、客户端下载和手工打开入口。
4. 客户端领取脚本、字段快照、数据集和环境信息。
5. 客户端本地执行 Playwright。
6. 报告、截图、录像和 Trace 上传平台。
7. 平台运行记录从排队中更新为执行中，再更新为最终结果。

自定义协议只携带平台地址和短期一次性凭证，不携带环境密码、脚本内容或测试数据。

## 11. 服务边界

后端职责拆分为以下独立模块：

- `recording-analysis`：解析 Codegen 脚本并生成字段、断言候选。
- `script-transform`：参数化、schema 更新和字段引用重命名。
- `schema-sync`：计算平台字段与脚本字段差异并应用解决方案。
- `dataset-migration`：预览并原子创建迁移后的数据集。
- `scenario-releases`：创建、列出、比较和恢复发布快照。
- `desktop-launch`：生成录制和执行的协议地址及回退信息。

`server/app.mjs` 仅负责 HTTP 参数、认证和响应，不继续堆叠上述领域逻辑。

## 12. 数据模型

新增发布版本表 `scenario_releases`：

- `id`
- `scenario_id`
- `version_no`
- `snapshot_json`
- `script_content`
- `script_hash`
- `created_by`
- `created_at`

数据集增加可选追溯字段：

- `schema_snapshot`
- `source_dataset_id`
- `migration_json`

场景表保留现有 `status` 和当前工作副本字段。发布版本不参与日常编辑，只用于展示、比较和恢复。

## 13. 错误处理

- 录制任务过期或已使用：提示重新生成录制码。
- 自定义协议未注册：不视为失败，直接展示绿色工具回退。
- 脚本语法错误：保留当前有效脚本并定位到错误行列。
- 字段存在未解决冲突：允许保存草稿，不允许发布。
- 数据迁移校验失败：不写入新数据集，保留预览结果供修正。
- 本地执行网络中断：客户端保留结果并支持重试上传。
- 发布写入失败：事务回滚，场景仍保持草稿。

## 14. 测试策略

### 单元测试

- Codegen 操作和 `expect` 提取。
- 脚本参数化与字段引用重命名。
- schema 差异、三种冲突解决方式。
- 数据集迁移、校验和回滚。
- 发布版本号、快照、比较和恢复。
- 自定义协议地址及敏感字段排除。

### API 集成测试

- 录制上传、分析、应用向导结果的完整链路。
- 脚本和平台字段双向同步。
- 草稿执行及发布版本创建。
- 本地执行领取、上传和完成。

### 桌面客户端测试

- 注册和解析 `autotest-recorder` 协议。
- 录制与执行两种启动参数。
- 未注册协议时的绿色工具兼容流程。

### 浏览器验收

- 从场景发起录制并完成三步向导。
- 在线修改字段并迁移已有数据集。
- 在线编辑脚本并解决 schema 冲突。
- 草稿本地执行、报告回传和发布。
- 发布多个版本并恢复旧版本。

## 15. 验收标准

1. 用户从点击“开始录制”到得到可执行草稿，不需要运行命令或手工上传文件。
2. 录制中的固定输入值可以在向导中转换为测试数据字段。
3. 没有编写代码也能增加至少一种成功条件。
4. 脚本、字段和测试数据都可以在线修改并通过保存校验。
5. 字段冲突必须明确展示，不能静默覆盖。
6. 字段迁移不修改原数据集，失败时不产生部分结果。
7. 草稿和已发布场景均可执行。
8. 本地执行优先一键唤起客户端，失败时仍能用绿色工具和执行码完成。
9. 每次发布生成一个不可变版本，并可查看、比较和恢复。
10. 服务器执行和本地执行产生一致的运行状态及报告入口。

## 16. 非目标

- 不增加测试人员、技术人员、审核人等角色差异。
- 不增加待审核、已退回等中间状态。
- 不建设通用低代码步骤编排器。
- 不自动生成复杂业务断言。
- 不把本地客户端变成必须安装的软件。
