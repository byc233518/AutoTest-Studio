# AutoTest Studio 绿色免安装本地录制器设计

## 背景

当前本地录制通过平台生成 `npm run record:local` 命令，由使用者在项目根目录执行。该流程要求同事提前安装 Node.js、项目依赖和 Playwright 浏览器，并理解工作目录、命令行参数、平台地址及上传 Token。新电脑或新检出的项目如果没有 `node_modules`，会直接出现找不到 `node_modules/playwright/cli.js` 的错误。

本设计将同事侧流程改造成绿色免安装 GUI 录制器：解压后双击运行，输入平台生成的短录制码即可启动 Playwright Inspector，关闭 Inspector 后自动上传脚本并绑定场景。

## 目标

- 同事电脑无需安装 Node.js、npm、Playwright、浏览器组件或 .NET Runtime。
- 不要求管理员权限，不修改注册表、系统 PATH 和文件关联。
- 同事无需进入命令行，也无需接触录制 ID、上传 Token 和完整启动参数。
- 继续使用现有 Playwright `codegen` 录制能力和脚本上传、场景绑定流程。
- 支持 Windows 10/11 x64，通过解压 ZIP 后直接运行。
- 录制失败时给出中文、可操作的错误提示，并保留必要的本地日志。

## 非目标

- 第一版不实现浏览器内远程桌面、远程控制或云端录制。
- 第一版不支持 macOS、Linux 和 Windows ARM。
- 第一版不实现静默自动更新；新版本仍通过重新下载 ZIP 分发。
- 不改变录制生成的 Playwright JavaScript 脚本格式。
- 不允许多人共享同一个录制码或上传凭证。

## 方案选择

采用“轻量 WinForms 外壳 + 内置便携 Node.js + 固定版本 Playwright + 内置 Chromium”的绿色包方案。

选择该方案的原因：

- WinForms 外壳可发布为自包含 Windows 可执行程序，同事电脑无需安装 .NET Runtime。
- Node.js、Playwright 和 Chromium 随包分发，运行结果不依赖同事电脑现有环境。
- 现有 `record-local.mjs` 和上传接口可以复用，改造范围集中。
- 相比 Electron，不需要再引入一套用于 GUI 的 Chromium，可控制安装包体积。
- 相比 PowerShell/WPF 脚本，不受执行策略、脚本签名和终端编码影响。

预计解压后体积为 350MB 至 500MB，主要来自 Playwright Chromium。第一版只包含 Chromium，不打包 Firefox 和 WebKit。

## 用户流程

### 首次使用

1. 同事从平台或共享目录下载 `AutoTest-Studio本地录制器-win-x64.zip`。
2. 解压到任意可写目录，例如 `D:\AutoTest-Studio录制器`。
3. 双击 `AutoTest-Studio录制器.exe`。
4. 首次启动时确认平台地址；默认填入团队统一的局域网平台地址，并保存到录制器目录下的本地配置文件。

### 每次录制

1. 在测试平台选择环境和测试场景，点击“本地录制”。
2. 平台展示一次性短录制码，例如 `7K3P-W9QM`，并提示有效期。
3. 同事打开录制器，输入或粘贴录制码，点击“开始录制”。
4. 录制器向平台换取本次录制参数并立即使录制码失效。
5. 录制器启动内置 Playwright Inspector 和 Chromium。
6. 同事在浏览器中完成操作后关闭 Inspector。
7. 录制器自动上传脚本，平台将脚本绑定到对应场景。
8. GUI 显示“上传成功”和绑定后的场景名称；同事可以关闭录制器或继续输入新的录制码。

整个流程不展示 npm 命令、上传 Token、文件路径和 Playwright CLI 参数。

## 绿色包结构

```text
AutoTest-Studio录制器/
├─ AutoTest-Studio录制器.exe
├─ recorder.config.json
├─ runtime/
│  └─ node.exe
├─ app/
│  ├─ record-runner.mjs
│  └─ node_modules/
├─ browsers/
│  ├─ chromium-<revision>/
│  └─ ffmpeg-<revision>/
├─ data/
│  ├─ recordings/
│  ├─ pending/
│  └─ logs/
└─ VERSION
```

- 所有运行路径根据 `AutoTest-Studio录制器.exe` 所在目录解析，不能依赖当前工作目录。
- 启动 Node 子进程时设置 `PLAYWRIGHT_BROWSERS_PATH=<录制器目录>\browsers`。
- 临时脚本写入 `data/recordings`；上传失败的脚本移动到 `data/pending`，避免丢失。
- 日志不得记录上传 Token、登录密码、Cookie 或页面表单内容。

## 平台接口设计

### 创建本地录制任务

继续使用现有：

```http
POST /api/recordings/start
```

当 `location=local` 时，响应新增：

```json
{
  "id": "REC-20260714044915-021171",
  "status": "recording",
  "location": "local",
  "startUrl": "http://172.16.100.11:46069/#/login",
  "recordCode": "7K3P-W9QM",
  "recordCodeExpires": "2026-07-14T13:20:00+08:00"
}
```

兼容期内保留当前 `localCommand` 和 `uploadToken` 字段，便于管理员排查和旧客户端继续工作；普通界面默认只展示录制码。

录制码使用排除 `0/O/1/I` 的大写字母和数字组成，共 8 位，显示时分成两组。服务端只保存录制码摘要，不保存明文。有效期沿用当前录制任务的 30 分钟限制。

### 录制码换取参数

新增：

```http
POST /api/recordings/resolve
Content-Type: application/json

{
  "code": "7K3P-W9QM"
}
```

成功响应：

```json
{
  "id": "REC-20260714044915-021171",
  "token": "<一次性上传凭证>",
  "startUrl": "http://172.16.100.11:46069/#/login",
  "expiresAt": "2026-07-14T13:20:00+08:00"
}
```

解析成功后立即标记录制码已使用，同一个录制码不能再次换取参数。接口按来源 IP 限速，并对无效、过期和已使用状态返回统一提示，避免泄露录制任务信息。

### 上传录制脚本

继续使用现有：

```http
POST /api/recordings/:id/upload
```

上传凭证仍由录制器通过表单字段提交。上传成功后服务端清除凭证并更新录制任务、脚本入口和场景绑定关系。

## 录制器组件

### GUI 外壳

GUI 只包含以下必要控件：

- 平台地址输入框，首次确认后记忆。
- 录制码输入框，自动忽略大小写、空格和连字符差异。
- “开始录制”“重试上传”“打开日志目录”按钮。
- 当前阶段、成功结果和中文错误信息展示区。

录制期间禁用平台地址和录制码输入，防止同一进程重复启动任务。关闭 GUI 时如果 Inspector 仍在运行，需要先提示用户确认是否取消。

### Node 录制执行器

现有 `scripts/record-local.mjs` 中的核心流程抽取为可复用执行模块：

1. 接收录制 ID、上传 Token、开始地址、平台地址和输出路径。
2. 使用录制器包内的 Playwright CLI 启动 `codegen`。
3. 等待 Inspector 退出。
4. 检查是否生成有效脚本。
5. 调用现有上传接口。
6. 通过标准输出向 GUI 返回结构化状态事件。

原有 npm 命令继续保留，用于开发和管理员诊断；GUI 与命令行入口调用同一执行模块，避免出现两套录制逻辑。

### 打包器

增加可重复执行的构建脚本，固定以下版本：

- 自包含 WinForms 录制器版本。
- Node.js Windows x64 版本。
- `package-lock.json` 锁定的 Playwright 版本。
- 与该 Playwright 版本匹配的 Chromium 和 FFmpeg revision。

构建脚本负责清理临时目录、复制最小依赖、安装浏览器到包内目录、生成版本文件并输出 ZIP。构建机器需要开发工具和网络，同事电脑不需要。

## 状态与错误处理

GUI 使用以下状态：

```text
空闲 -> 解析录制码 -> 启动浏览器 -> 录制中 -> 上传中 -> 完成
                                      └-> 已取消
                         任意阶段失败 -> 可恢复错误
```

需要明确处理：

- 平台地址不可访问：提示检查平台地址、网络和 3050 端口。
- 录制码无效、过期或已使用：提示回到平台重新发起录制。
- 目标系统不可访问：保留任务状态并提示检查测试环境网络。
- 内置浏览器缺失或损坏：提示重新下载完整绿色包。
- 用户未生成脚本便关闭 Inspector：标记为取消，不上传空文件。
- 上传失败但凭证仍有效：保留脚本并允许点击“重试上传”。
- 上传凭证过期：保留脚本到 `data/pending`，提示重新发起录制并联系管理员处理旧脚本。
- 子进程异常退出：显示退出码和日志编号，不直接展示敏感参数。

## 安全设计

- 录制码一次性使用且最多有效 30 分钟。
- 上传 Token 不显示在 GUI、日志、剪贴板和进程窗口标题中。
- 解析接口进行 IP 限速，并记录失败次数和时间，不记录用户输入的完整录制码。
- 录制器只接受 `http` 或 `https` 平台地址，并拒绝 URL 中的用户名、密码和非预期协议。
- 绿色包发布时生成 SHA-256 校验文件；条件允许时对 EXE 进行企业代码签名，减少 SmartScreen 和杀毒软件拦截。
- 录制脚本可能包含测试页面操作数据，上传成功后默认删除本地临时文件；上传失败文件由用户主动清理或在后续版本增加过期清理策略。

## 兼容与发布策略

- 第一阶段保留现有命令行录制方式，绿色录制器作为推荐入口。
- 平台提供“下载免安装录制器”和版本号说明，下载地址由配置项控制，可指向平台静态文件或团队文件服务器。
- 录制器请求平台时携带自身版本，平台可以提示版本过旧；第一版只提示，不自动更新。
- 新版本绿色包使用全新目录解压，避免覆盖仍在使用的旧版和未上传脚本。

## 代码影响范围

- `server/app.mjs`：创建录制码、增加录制码解析接口和限速校验。
- `server/platform/recordings.mjs`：录制码生成、摘要、过期及一次性消费逻辑。
- `frontend/src/components/ScenarioDrawer.vue`：本地录制弹窗改为展示录制码、有效期和录制器下载入口。
- `scripts/record-local.mjs`：保留 CLI 入口并改为调用共享执行模块。
- `scripts/`：增加绿色包构建脚本和版本校验脚本。
- `recorder/`：新增 WinForms GUI 录制器工程。
- `tests/`：增加录制码、上传兼容、执行器和打包完整性测试。
- `docs/`：增加同事使用说明和维护发布说明。

## 测试方案

### 单元测试

- 录制码格式、摘要、有效期和一次性消费。
- 无效、过期、重复使用录制码的返回结果。
- 平台地址、录制码规范化和配置文件读写。
- 录制器运行目录解析不受当前工作目录影响。
- 状态事件中不包含上传 Token。

### 集成测试

- 创建本地录制任务、使用录制码换取参数、上传脚本、完成场景绑定的完整链路。
- 旧版 `record:local` 命令在兼容期内仍能完成上传。
- Inspector 正常关闭、未生成脚本、异常退出和上传重试流程。
- 两个同事同时使用不同录制码时互不影响。

### 干净环境验收

在一台没有安装 Node.js、npm、Playwright 和 .NET Runtime 的 Windows 10/11 x64 虚拟机上验证：

1. 解压 ZIP 后无需管理员权限即可启动。
2. 输入平台地址和录制码后一分钟内打开 Inspector。
3. 可以访问 AutoTest Studio 测试环境并完成一次操作录制。
4. 关闭 Inspector 后脚本自动上传并绑定场景。
5. 平台显示完成状态，脚本可以正常执行。
6. 全流程不打开命令行窗口，不要求用户编辑配置文件。

## 验收标准

1. 新同事只需下载、解压、双击和输入录制码即可完成录制。
2. 同事电脑无需预装任何开发工具和浏览器组件。
3. 录制器不依赖启动目录和系统 PATH。
4. 录制成功后平台脚本入口、场景绑定和状态与现有流程一致。
5. 无效或过期录制码不会获得上传 Token。
6. GUI 和日志不泄露上传 Token、Cookie、密码等敏感信息。
7. 绿色包可以通过单一构建命令重复生成，并能校验运行时与浏览器文件完整性。
