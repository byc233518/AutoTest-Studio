# AutoTest Studio 免安装录制器使用说明

## 适用环境

- Windows 10/11 x64。
- 可以访问测试自动化平台和 AutoTest Studio 测试环境。
- 不需要管理员权限。
- 不需要安装 Node.js、npm、Playwright、Chrome 或 .NET Runtime。

## 下载与校验

在场景详情的“脚本与录制”页签点击“下载免安装录制器”，或从本机执行弹窗、团队共享目录获取：

- `AutoTest-Studio本地录制器-win-x64.zip`
- `AutoTest-Studio本地录制器-win-x64.zip.sha256`

建议在 PowerShell 中校验文件：

```powershell
Get-FileHash .\AutoTest-Studio本地录制器-win-x64.zip -Algorithm SHA256
Get-Content .\AutoTest-Studio本地录制器-win-x64.zip.sha256
```

两处哈希值必须一致。校验后将 ZIP 解压到任意可写目录，例如 `D:\AutoTest-Studio录制器`。不要直接在压缩包预览窗口中运行 EXE。

## 开始录制

1. 登录测试自动化平台。
2. 打开需要维护的测试场景。
3. 进入“脚本与录制”页签并选择测试环境。
4. 点击“开始录制”。
5. 浏览器会尝试通过 `autotest-recorder://record` 一键打开录制器。
6. 如果没有自动打开，复制平台显示的 8 位录制码，例如 `7K3P-W9QM`，再双击解压目录中的 `AutoTest-Studio录制器.exe`。
7. 首次使用时填写平台局域网地址，例如 `http://172.16.100.20:3050`。同事使用共享平台时不能填写 `http://localhost:3050`。
8. 功能选择“录制场景”，输入录制码并点击“开始录制”。
9. Playwright Inspector 和目标系统浏览器打开后，按实际业务流程完成操作。
10. 操作完成后关闭 Inspector。
11. 等待录制器显示“录制脚本已上传”。平台会自动打开复核向导，确认字段、成功条件和最终脚本后应用到草稿场景。

录制码在生成后 30 分钟内有效，并且只能成功换取一次录制参数。录制器已经开始运行后，不要把同一个录制码交给其他人使用。

## 执行场景

1. 登录测试自动化平台。
2. 在场景列表或场景详情点击“执行”。
3. 选择环境、执行模式和测试数据，将“执行位置”切换为“本机执行”。
4. 点击“开始执行”后，平台会弹出本机执行窗口，并尝试通过 `autotest-recorder://execute` 一键打开录制器。
5. 如果没有自动打开，复制窗口中的 8 位操作码，打开 `AutoTest-Studio录制器.exe`。
6. 功能选择“执行场景”，确认平台地址，输入操作码并开始执行。
7. 录制器会下载本次执行的脚本、数据和环境配置，在本机运行 Playwright，并将状态、截图、录像、Trace 和报告回传平台。

执行码同样 30 分钟内有效且只能使用一次。平台窗口中可以再次打开本地工具、复制操作码或下载绿色工具。

## 上传失败重试

如果录制已经完成但上传时网络中断，录制器会保留当前进程中的上传凭证并启用“重试上传”按钮：

1. 确认平台地址可以访问。
2. 不要关闭录制器。
3. 点击“重试上传”。
4. 上传成功后录制器会自动清理本地临时脚本。

如果录制器进程已经关闭或凭证已过期，需要回到平台重新点击“开始录制”，使用新的录制码重新录制。

## 常见问题

### 提示录制码无效或已过期

录制码可能超过 30 分钟、已被使用或输入错误。回到平台重新发起本地录制并复制新录制码。

### 提示执行码无效或已过期

执行码可能超过 30 分钟、已被领取、输入错误，或不是在同一个平台生成。回到平台重新创建本机执行任务。

### 提示平台地址无法访问

共享平台应填写平台电脑的局域网地址，而不是 `localhost`。可以测试：

```powershell
Test-NetConnection 平台电脑IP -Port 3050
```

### 提示运行时或浏览器文件缺失

绿色包可能没有完整解压，或文件被安全软件隔离。重新下载 ZIP、核对 SHA-256，然后解压到新目录。

### Inspector 未生成脚本

如果没有完成任何操作便关闭 Inspector，录制器会将本次任务视为取消，不会上传空脚本。回到平台重新发起录制。

### 查看日志

点击录制器中的“打开日志目录”，或打开：

```text
<录制器目录>\data\logs
```

日志不会记录上传 Token、登录密码或 Cookie。向维护人员反馈时，请提供最新日志文件、录制任务编号和错误发生时间。

## 管理员构建与发布

### 构建环境

免安装录制器必须在 **Windows x64** 机器上构建，不能直接在 Linux 部署服务器中执行构建。构建机需要：

- Node.js 22。
- .NET SDK 10。
- PowerShell 5.1 或更高版本。
- 可以访问 npm 和 Playwright 浏览器下载源。

在 PowerShell 中检查环境：

```powershell
node --version
npm --version
dotnet --version
$PSVersionTable.PSVersion
```

### 首次构建或依赖更新后构建

在 Windows 项目根目录执行：

```powershell
Set-Location 'F:\workspace\jmom\测试自动化'
npm ci
npm run test:recorder
npm run build:recorder
```

日常只修改了录制器代码、依赖没有变化时，可以直接执行：

```powershell
Set-Location 'F:\workspace\jmom\测试自动化'
npm run build:recorder
```

构建产物位于：

```text
dist\AutoTest-Studio本地录制器-win-x64.zip
dist\AutoTest-Studio本地录制器-win-x64.zip.sha256
```

检查构建产物：

```powershell
Get-Item '.\dist\AutoTest-Studio本地录制器-win-x64.zip'
Get-FileHash '.\dist\AutoTest-Studio本地录制器-win-x64.zip' -Algorithm SHA256
Get-Content '.\dist\AutoTest-Studio本地录制器-win-x64.zip.sha256'
```

### 发布到 Docker 服务器

`dist` 目录不会提交到 Git，因此仅在服务器上执行 `git pull` 不会得到录制器 ZIP。需要先在 Windows 构建机生成 ZIP，再上传到服务器仓库的 `dist` 目录。

以下示例假设服务器仓库位于 `/data2/QTP`，请将 `<服务器用户>` 和 `<服务器地址>` 替换为实际值：

```powershell
ssh <服务器用户>@<服务器地址> "mkdir -p /data2/QTP/dist"
scp '.\dist\AutoTest-Studio本地录制器-win-x64.zip' '<服务器用户>@<服务器地址>:/data2/QTP/dist/'
scp '.\dist\AutoTest-Studio本地录制器-win-x64.zip.sha256' '<服务器用户>@<服务器地址>:/data2/QTP/dist/'
```

上传完成后，在 Linux 服务器执行：

```bash
cd /data2/QTP
ls -lh dist/AutoTest-Studio本地录制器-win-x64.zip*
(cd dist && sha256sum -c AutoTest-Studio本地录制器-win-x64.zip.sha256)
sh docker/docker-deploy.sh
docker exec autotest-studio test -f /app/dist/AutoTest-Studio本地录制器-win-x64.zip
```

最后登录平台，在场景详情的“脚本与录制”页签点击“下载免安装录制器”验证下载。如果仍提示“免安装录制器尚未构建”，执行：

```bash
docker exec autotest-studio ls -lh /app/dist/
docker logs --tail=200 autotest-studio
```

平台默认从上述 ZIP 路径提供下载。部署时也可以通过 `AUTOTEST_RECORDER_PACKAGE` 环境变量指定实际文件路径。
