# 测试人员使用手册

面向 **AutoTest Studio Windows 桌面客户端**。默认完全本机离线使用：用例、数据、报告都保存在项目目录中。

## 安装与打开项目

1. 安装 Windows x64 客户端（或开发环境执行 `npm.cmd run desktop`）。
2. 首次打开会准备默认项目；之后用「新建项目」即可，不必先选目录（默认写入安装目录下的 `projects`）。也可「打开已有项目」或「导入项目」。
3. 用左上角项目切换器在多个项目间切换。当前项目不显示删除图标；切到其它项目后再删。默认可只从列表移除；勾选后会连同项目目录一起删除。
4. **导出 / 导入项目**：在项目菜单中把整个项目打成 zip 带走，或解压到空目录后打开。导入同 ID 项目时会自动换新 ID。

目标电脑需安装 Google Chrome 或 Microsoft Edge。客户端优先用 Chrome，没有则用 Edge；执行与录制使用独立临时用户目录，不读取日常浏览器账号。

## 日常回归（推荐顺序）

1. **环境配置**：确认当前项目的 Base URL、账号、密码和全局变量。
2. **测试用例**：优先勾选状态为「可执行」的用例；「需准备」按提示补脚本、数据或环境；「草稿」先维护再发布。
3. **录制 / 改脚本**：在用例详情中录制或编辑 Playwright 脚本，维护测试数据字段。
4. **单条执行**：在用例列表执行，选择环境、执行模式和数据集。
5. **测试计划**：把多个可执行用例编成计划，选择各自测试数据后批量执行。
6. **执行报告**：在「执行报告」或计划详情查看结果、截图、录像；计划报告可按「报告模板」输出 Markdown / HTML / Word。

## 用例状态

- **可执行**：已发布、脚本已绑定、环境存在、依赖已通过；若用例配置了数据字段，还需要有效数据集。没有数据字段的用例不必准备测试数据。
- **需准备**：至少一项执行前检查未通过，按悬停提示补齐。
- **草稿**：尚未发布，适合录制后复核、改字段和补断言。

## 测试数据

命名建议用「场景 + 环境 + 用途 + 日期」，例如：`表单提交-测试环境-冒烟-20260929`。没有数据字段的用例可以跳过这一步。

支持 JSON / CSV / Excel 导入、在线填表、规则生成样例，以及可选的 AI 生成（需在「AI 配置」中启用）。

## 失败后怎么处理

1. 看业务摘要中的总数、通过数、失败数。
2. 下载失败数据 CSV，按错误信息修正。
3. 上传为新数据集后重跑；原始失败证据不会被覆盖。
4. 需要定位技术问题时，再看截图、录像、Trace 和 HTML 报告。

## 报告模板

在 **系统配置 → 报告模板** 中维护模块、是否含截图、输出格式，并将某一模板设为「当前启用」后保存。之后的计划 / 批量执行会按该模板生成报告；历史批次不会自动重写。

## 系统配置常用项

| 菜单 | 用途 |
|------|------|
| 环境配置 | 被测系统地址与账号 |
| AI 配置 | 智能数据生成与计划总结（可选） |
| 报告模板 | 报告模块、截图、Markdown/HTML/Word |
| 通用设置 | 主题、本机浏览器、测试单位 / 人员 / 落款 |

## 管理建议

- 正式用例填写负责人、业务断言说明和适用环境。
- 录制结果先留草稿，复核字段与断言后再发布。
- 不同客户 / 产品线用不同项目目录隔离，避免混用数据。
