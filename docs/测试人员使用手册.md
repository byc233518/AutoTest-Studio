# 测试人员使用手册

## 三步完成一次回归

1. 在“测试场景”中优先选择标记为“可执行”的场景。
2. 如果显示“需准备”，按推荐任务补充脚本、数据集、环境或前置依赖。
3. 执行完成后进入“执行与报告”，先查看业务摘要，再按需查看截图、录像和技术报告。

## 场景状态

- **可执行**：已发布、脚本已绑定、有效数据集存在、环境存在、依赖已通过。
- **需准备**：至少一项执行前检查未通过，鼠标悬停执行按钮可查看下一步。
- **草稿**：尚未发布，建议在草稿阶段完成脚本和数据维护。

## 数据集命名建议

使用“场景 + 环境 + 用途 + 日期”，例如：`客户主数据-测试环境-冒烟-20260711`。避免使用“数据集1”“1234”等无法识别用途的名称。

## 执行失败处理

1. 查看业务摘要中的总数、成功数和失败数。
2. 下载失败数据 CSV，按错误信息修正。
3. 上传为新的数据集后重新执行；平台不会覆盖原始失败证据。
4. 定位技术问题时再查看过程截图、录像和 HTML 报告。

## 测试套件

平台内置：
- 核心冒烟测试
- WMS 主数据初始化
- MES 生产链回归

套件会先检查所有场景是否就绪，并列出阻塞项，避免执行到一半才发现缺少数据。

## 管理建议

- 正式场景必须填写负责人、业务断言说明和适用环境。
- 录制产生的场景先保留为草稿，通过评审后再发布。
- 每周关注最近十次成功率和失败次数，及时处理不稳定场景。
